## Authentication

All endpoints require the following headers unless otherwise noted:

<ParamField header="Authorization" type="string" required>
Bearer token (JWT) for end-user authentication. Format: `Bearer YOUR_JWT_TOKEN`
</ParamField>

<ParamField header="X-MAGIC-SECRET-KEY" type="string" required>
Your Magic secret key for application-level authentication.
</ParamField>

## Sign Data

Sign data with the authenticated user's Magic wallet.

```bash cURL icon="square-terminal"
curl -X POST 'https://uoa-server.magic.xyz/wallet/sign' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer USER_JWT_TOKEN' \
  -H 'X-MAGIC-SECRET-KEY: YOUR_MAGIC_SECRET_KEY' \
  -d '{
    "message": "Hello, world!"
  }'
```

To sign EIP-712 typed data, send it as `transaction_data` instead of `message`:

```bash cURL icon="square-terminal"
curl -X POST 'https://uoa-server.magic.xyz/wallet/sign' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer USER_JWT_TOKEN' \
  -H 'X-MAGIC-SECRET-KEY: YOUR_MAGIC_SECRET_KEY' \
  -d '{
    "raw_data_hash": "0xe8290d5c9c62619dfbd74f495ab122e6375312f767a4ff983d4e2d55a94078b9",
    "transaction_data": {
      "method": "eth_signTypedData_v4",
      "typedData": {
        "types": {
          "EIP712Domain": [
            { "name": "name", "type": "string" },
            { "name": "version", "type": "string" },
            { "name": "chainId", "type": "uint256" }
          ],
          "ClobAuth": [
            { "name": "address", "type": "address" },
            { "name": "timestamp", "type": "string" },
            { "name": "nonce", "type": "uint256" },
            { "name": "message", "type": "string" }
          ]
        },
        "primaryType": "ClobAuth",
        "domain": { "name": "ClobAuthDomain", "version": "1", "chainId": "137" },
        "message": {
          "address": "0x1111111111111111111111111111111111111111",
          "timestamp": "1762700000",
          "nonce": "0",
          "message": "This message attests that I control the given wallet"
        }
      }
    }
  }'
```

**Response:**

```json
{
  "success": true,
  "signature": "0xabcdef1234567890...",
  "raw_data_hash": "0x1234567890abcdef...",
  "app_user_id": "user-123"
}
```

### Request Parameters

Provide either `message` or `transaction_data`.

<ParamField body="message" type="string">
A plain text message to sign. It is signed as an EIP-191 (`personal_sign`) message over its UTF-8 bytes, so you can verify it with standard tools such as ethers' `verifyMessage`.
</ParamField>

<ParamField body="transaction_data" type="object">
What to sign, in one of two forms:

- **EIP-712 typed data:** `{"method": "eth_signTypedData_v4", "typedData": {...}}`. `typedData` has `types` (including `EIP712Domain`), `primaryType`, `domain` and `message`, as passed to `eth_signTypedData_v4`. The signature is over the typed data's EIP-712 digest, so it verifies with ethers' `verifyTypedData` (pass `types` without `EIP712Domain`).
- **A Polymarket Safe transaction:** `{"method": "eth_sign", "data": "<SafeTx hash>", "safeTxTypedData": {...}}`. See [Polymarket Safe transactions](#polymarket-safe-transactions).
</ParamField>

<ParamField body="raw_data_hash" type="string">
With `transaction_data`, the hash you computed: the EIP-712 digest of `typedData`, or for a Safe transaction the EIP-191 hash of the SafeTx hash. Optional; if you send it and it doesn't match, the request returns `400`.
</ParamField>

<Warning>
Signing a bare hash is not supported. A request with `raw_data_hash` and neither `message` nor `transaction_data` returns `400`. `transaction_data` accepts only `eth_signTypedData_v4` typed data and Polymarket Safe transactions.
</Warning>

### Polymarket Safe transactions

Polymarket's relayer only accepts Safe signatures in the `eth_sign` style: EIP-191 over the 32-byte SafeTx hash. To get one, send the SafeTx hash as `data` and the SafeTx it was computed from as `safeTxTypedData`:

```json
{
  "raw_data_hash": "<EIP-191 hash of the SafeTx hash>",
  "transaction_data": {
    "method": "eth_sign",
    "data": "<SafeTx hash>",
    "safeTxTypedData": {
      "types": {
        "EIP712Domain": [
          { "name": "chainId", "type": "uint256" },
          { "name": "verifyingContract", "type": "address" }
        ],
        "SafeTx": [
          { "name": "to", "type": "address" },
          { "name": "value", "type": "uint256" },
          { "name": "data", "type": "bytes" },
          { "name": "operation", "type": "uint8" },
          { "name": "safeTxGas", "type": "uint256" },
          { "name": "baseGas", "type": "uint256" },
          { "name": "gasPrice", "type": "uint256" },
          { "name": "gasToken", "type": "address" },
          { "name": "refundReceiver", "type": "address" },
          { "name": "nonce", "type": "uint256" }
        ]
      },
      "primaryType": "SafeTx",
      "domain": { "chainId": "137", "verifyingContract": "<the user's Polymarket Safe>" },
      "message": {
        "to": "<contract address>",
        "value": "0",
        "data": "<0x-prefixed calldata>",
        "operation": "0",
        "safeTxGas": "0",
        "baseGas": "0",
        "gasPrice": "0",
        "gasToken": "0x0000000000000000000000000000000000000000",
        "refundReceiver": "0x0000000000000000000000000000000000000000",
        "nonce": "<the Safe's current nonce>"
      }
    }
  }
}
```

The SafeTx is checked before anything is signed. The request returns `400` unless:

- `safeTxTypedData` is a SafeTx with exactly the types above, and `data` is its EIP-712 hash
- `chainId` is `137` and `verifyingContract` is the user's own Polymarket Safe, the one Polymarket's relayer derives from the user's wallet address
- a `delegatecall` (`operation: 1`) goes only to Polymarket's MultiSend, and every transaction batched inside it is a plain call
- no call, top-level or batched, is made to the Safe itself

The returned `signature` is a plain ECDSA signature over the EIP-191 hash. Before submitting it to the relayer, pack it as Safe expects for `eth_sign` signatures: `r`, `s`, then a `v` of 31 or 32 (add 4 to a `v` of 27 or 28, or 31 to a `v` of 0 or 1).

### Response Fields

<ResponseField name="success" type="boolean">
Whether the signing operation completed successfully.
</ResponseField>

<ResponseField name="signature" type="string">
The hex-encoded signature.
</ResponseField>

<ResponseField name="raw_data_hash" type="string">
The hash that was signed: the EIP-191 hash of `message`, or the EIP-712 digest of `transaction_data.typedData`.
</ResponseField>

<ResponseField name="app_user_id" type="string">
The user identifier from your application.
</ResponseField>

## Withdraw to External Address

Send funds from the authenticated user's Magic wallet to an external address.

```bash cURL icon="square-terminal"
curl -X POST 'https://uoa-server.magic.xyz/withdraw' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer USER_JWT_TOKEN' \
  -H 'X-MAGIC-SECRET-KEY: YOUR_MAGIC_SECRET_KEY' \
  -d '{
    "to_address": "0xRecipientAddress...",
    "amount": "50",
    "token": "USDC",
    "chain": "ARB"
  }'
```

**Response:**

`message` is generated by the server (success text includes amount, token, and chain, and notes EIP-7702 gas-sponsored sends when applicable). `tx_hash` is an EVM transaction hash (`0x…`) or a Solana signature string depending on `chain`.

```json
{
  "success": true,
  "tx_hash": "0xabcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890",
  "from_address": "0x1234567890abcdef1234567890abcdef12345678",
  "to_address": "0x742d35Cc6634C0532925a3b844Bc454e4438f44e",
  "amount": "50",
  "token": "USDC",
  "chain": "ARB",
  "message": "Successfully sent 50 USDC on ARB"
}
```

### Request Parameters

<ParamField body="to_address" type="string" required>
The recipient wallet address. EVM destinations are normalized to checksummed hex; Solana addresses are validated as base58.
</ParamField>

<ParamField body="amount" type="string" required>
The amount to withdraw as a decimal string.
</ParamField>

<ParamField body="token" type="string" default="USDC">
The token to withdraw. Values: `ETH`, `USDC`, `USDC.E`, `POL`, `SOL`
</ParamField>

<ParamField body="chain" type="string" default="ARB">
The chain to withdraw on. Values: `ETH`, `ARB`, `POL`, `SOL`, `INK`
</ParamField>

<ParamField body="gas_sponsored" type="boolean" default="false">
Request gas-sponsored execution for **EVM** withdrawals when supported (Alchemy EIP-7702 path). Ignored for Solana (`should_sponsor_gas` is false on SOL).
</ParamField>

### Supported Token/Chain Combinations

| Chain | Supported Tokens |
|-------|-----------------|
| ETH | ETH, USDC |
| ARB | ETH, USDC, USDC.E |
| POL | POL, USDC, USDC.E |
| SOL | SOL, USDC |
| INK | ETH, USDC |

<ResponseField name="success" type="boolean">

</ResponseField>

<ResponseField name="from_address" type="string">
The sender's wallet address.

</ResponseField>

The token that was withdrawn.
</ResponseField>

<ResponseField name="chain" type="string">
The chain the withdrawal was executed on.
</ResponseField>

Human-readable status message describing the completed withdrawal.
</ResponseField>
